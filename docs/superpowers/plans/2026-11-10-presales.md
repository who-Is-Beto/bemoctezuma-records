# Preventas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Presales with options, deposits/full payment, a per-order payment ledger, pickup/shipping, delivery by code, a double-opt-in announcement list, and Ventas integration.

**Architecture:** Backend: one new domain module per package (`models/presales.py`, `services/presales.py`, `serilizers/presales.py`, `views/presales.py`, `views/presales_admin.py`), all money rules in the service (views stay thin), Stripe reusing the existing webhook with `metadata.kind = "presale"`. Frontend: `domain/presales.ts` + `services/presaleService.ts` (repository pattern), home section, `/preventas/:slug`, presale cards in Mis órdenes, a "Preventas" Administración tab.

**Tech Stack:** Django 5.2 / DRF 3.16 / Stripe / Envíos Perros (`services/shipping.py`) / Resend via `send_email`; React 19 / Vite / TS / Tailwind 3.4.

**Spec:** `docs/superpowers/specs/2026-11-10-presales-design.md`

## Review Focus

1. **Two people take the last copy at once** → exactly one gets it; the other sees "Agotado" (Task 2: `test_reserve_last_copy_is_locked`).
2. **Stripe pays after the 30-min hold expired and the copy went to someone else** → the payment is still recorded (money taken), order kept, store emailed "sobreventa" (Task 4: `test_late_payment_after_hold_expired_is_kept_and_flagged`).
3. **Webhook and success page both fulfil the same session** → one payment row (Task 4: `test_presale_fulfilment_is_idempotent`).
4. **Voiding a payment of a paid order** → status back to `apartado`, `paid_at` cleared, leaves Ventas (Task 2: `test_void_reopens_balance_and_clears_paid_at`; Task 8 checks metrics).
5. **Customer edits the amount in the browser** (below minimum, above balance, non-numeric, more decimals) → 400, never charged (Task 4: `test_reserve_rejects_bad_amounts`).

### Task 2: Money & state service

**Files:** Create `apiApp/services/presales.py`; modify `apiApp/services/__init__.py`. Test `apiApp/tests/test_presales_service.py`.

**Interfaces — Produces** (all in `services/presales.py`):
- `DEPOSIT_DAYS = 120`, `AFTER_ARRIVAL_DAYS = 15`, `HOLD_MINUTES = 30`, `TERMS_VERSION = '2026-11'`.
- `copies_left(option) -> int` — `copies` minus orders in `apartado/pagado/listo/enviado/entregado` and `pending_payment` with `hold_expires_at > now`.
- `paid_amount(order) -> Decimal` (non-voided payments), `total_due(order) -> Decimal` (`item_price + (shipping_cost or 0)`), `balance(order) -> Decimal`, `shipping_pending(order) -> bool` (shipping delivery and `shipping_cost is None`).
- `deadline(order) -> date`: `max(localdate(reserved_at) + 120d, localdate(option.arrived_at) + 15d if arrived, deadline_override)`.
- `is_expirable(order) -> bool`: arrived, `localdate() > deadline(order)`, `balance > 0`, status `apartado`/`pagado`.
- `refresh_status(order, actor=None) -> None`: never touches `pending_payment` (except to `apartado`/`pagado` after a payment), `enviado`, `entregado`, `vencido`, `cancelado`. Paid ≥ `item_price` → `pagado` (sets `paid_at` if empty) else `apartado` (clears `paid_at`). Then `pagado` + option arrived + `balance == 0` + pickup → `listo`; `listo` with `balance > 0` → back to `pagado`. Logs a `status` event on change.
- `split_amount(option, amount, delivery, shipping_quote) -> dict` → `{'item_price', 'discount', 'shipping_cost', 'charge'}`: amount ≥ `price - discount` ⇒ full (`item_price = price - discount`, shipping charged now = quote, `charge = item_price + quote`); amount > `price` ⇒ `PresaleError('invalid_amount')`; amounts in [`price - discount`, `price`] are full payment charged at `price - discount`; else `min_deposit <= amount` ⇒ deposit (`item_price = price`, no shipping, `charge = amount`); else `PresaleError('amount_too_low')`. Amounts quantized to 0.01; more than 2 decimals ⇒ `PresaleError('invalid_amount')`.
- `create_order(option, *, buyer, source, delivery, shipping_details, amount, method=None, shipping_quote=None, created_by=None, accept_terms) -> PreSaleOrder` — `transaction.atomic()` + `select_for_update()` on the option; raises `PresaleError` codes: `terms_required`, `sold_out`, `deadline_passed`, `inactive`. Online (`method=None`) ⇒ `pending_payment` + `hold_expires_at = now + 30 min`; admin ⇒ immediately records a payment with `method`.
- `record_payment(order, amount, method, *, note='', registered_by=None, stripe_session_id=None) -> PreSalePayment` — rejects `amount <= 0` and `amount > balance` (`PresaleError('amount_exceeds_balance')`) except Stripe (trust Stripe); calls `refresh_status`; logs event; returns the existing row if `stripe_session_id` already recorded.
- `void_payment(payment, *, by, reason) -> None` (reason required) → `refresh_status`.
- `mark_arrived(option, *, by) -> None` — sets `arrived_at`, refreshes every order, logs events. Emails come from Task 7 via `emailing`.
- `deliver(order, *, by) -> None` — `PresaleError('balance_due')` if balance > 0 or shipping pending; `PresaleError('already_delivered')` if `entregado`; pickup only (shipping uses `mark_shipped`).
- `mark_shipped(order, *, tracking, by)`, `cancel(order, *, by, reason)`, `expire(order, *, by)` (requires `is_expirable`), `reopen(order, *, by)` (only `vencido`/`cancelado`, requires `copies_left > 0`, locked).
- `class PresaleError(Exception)` with `.code` and Spanish `.message`.
